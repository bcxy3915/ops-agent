# 监控指标说明

本文档定义了运维智能体关注的**所有核心监控指标**，包括指标含义、正常范围、告警阈值、查询方式和处理建议。

指标来源于 Spring Boot Actuator + Micrometer，通过 `/actuator/metrics/{name}` 暴露。

---

## 一、JVM 指标

### 1.1 内存指标

#### jvm.memory.used
- **含义**：JVM 已使用的内存量（字节）
- **标签**：`area`（heap / nonheap）、`id`（具体区域）
- **正常范围**：堆内存 < 最大堆的 70%
- **告警阈值**：> 90%
- **查询**：`/actuator/metrics/jvm.memory.used`
- **处理建议**：检查是否有大对象、内存泄漏，考虑调大堆或重启

#### jvm.memory.max
- **含义**：JVM 最大可用内存（字节）
- **正常范围**：固定值，由 `-Xmx` 决定
- **查询**：`/actuator/metrics/jvm.memory.max`
- **用途**：和 `jvm.memory.used` 对比，算内存使用率

#### jvm.memory.committed
- **含义**：JVM 已提交的内存（字节）
- **正常范围**：<= max
- **查询**：`/actuator/metrics/jvm.memory.committed`
- **用途**：观察内存池的扩展趋势

#### jvm.memory.usage.after.gc
- **含义**：最近一次 GC 后的内存使用率
- **正常范围**：< 50%
- **告警阈值**：> 70%
- **查询**：`/actuator/metrics/jvm.memory.usage.after.gc`
- **处理建议**：持续偏高说明有内存泄漏

#### jvm.buffer.memory.used
- **含义**：JVM 缓冲区使用的内存（NIO 直接内存）
- **正常范围**：< 100MB
- **告警阈值**：> 500MB
- **查询**：`/actuator/metrics/jvm.buffer.memory.used`
- **处理建议**：检查 NIO 使用，可能未释放 ByteBuffer

---

### 1.2 GC 指标

#### jvm.gc.pause
- **含义**：GC 暂停时间（秒）
- **标签**：`cause`（GC 原因）、`action`（GC 类型）
- **正常范围**：平均 < 100ms
- **告警阈值**：单次 > 500ms
- **查询**：`/actuator/metrics/jvm.gc.pause`
- **处理建议**：检查堆大小、GC 参数，考虑换 G1 或 ZGC

#### jvm.gc.memory.promoted
- **含义**：GC 时晋升到老年代的内存量（字节）
- **正常范围**：稳定波动
- **告警阈值**：持续增长
- **查询**：`/actuator/metrics/jvm.gc.memory.promoted`
- **处理建议**：晋升过快说明新生代太小或对象生命周期长

#### jvm.gc.memory.allocated
- **含义**：GC 期间分配的年轻代内存增长量（字节）
- **正常范围**：稳定波动
- **告警阈值**：突增
- **查询**：`/actuator/metrics/jvm.gc.memory.allocated`
- **处理建议**：说明对象创建速率突增

#### jvm.gc.live.data.size
- **含义**：Full GC 后老年代存活对象大小（字节）
- **正常范围**：稳定
- **告警阈值**：持续增长
- **查询**：`/actuator/metrics/jvm.gc.live.data.size`
- **处理建议**：增长说明内存泄漏

#### jvm.gc.max.data.size
- **含义**：老年代最大可用内存（字节）
- **查询**：`/actuator/metrics/jvm.gc.max.data.size`
- **用途**：和 live.data.size 对比算老年代使用率

---

### 1.3 线程指标

#### jvm.threads.live
- **含义**：当前活跃线程数
- **正常范围**：< 200
- **告警阈值**：> 500
- **查询**：`/actuator/metrics/jvm.threads.live`
- **处理建议**：检查线程池配置、是否有线程泄漏

#### jvm.threads.daemon
- **含义**：守护线程数
- **正常范围**：稳定
- **查询**：`/actuator/metrics/jvm.threads.daemon`

#### jvm.threads.peak
- **含义**：峰值线程数
- **正常范围**：< 500
- **告警阈值**：> 1000
- **查询**：`/actuator/metrics/jvm.threads.peak`

#### jvm.threads.states
- **含义**：各状态线程数（RUNNABLE / BLOCKED / WAITING / TIMED_WAITING）
- **标签**：`state`
- **正常范围**：BLOCKED < 10
- **告警阈值**：BLOCKED > 50
- **查询**：`/actuator/metrics/jvm.threads.states`
- **处理建议**：BLOCKED 多说明有锁竞争

---

### 1.4 类加载指标

#### jvm.classes.loaded
- **含义**：已加载的类数量
- **正常范围**：< 20000
- **告警阈值**：持续增长
- **查询**：`/actuator/metrics/jvm.classes.loaded`
- **处理建议**：持续增长说明类加载器泄漏

#### jvm.classes.unloaded
- **含义**：已卸载的类数量
- **正常范围**：稳定
- **查询**：`/actuator/metrics/jvm.classes.unloaded`

## 二、系统指标

### 2.1 CPU 指标

#### system.cpu.usage
- **含义**：系统 CPU 使用率
- **正常范围**：< 60%
- **告警阈值**：> 80%
- **查询**：`/actuator/metrics/system.cpu.usage`
- **处理建议**：检查死循环、GC、线程数

#### process.cpu.usage
- **含义**：当前进程 CPU 使用率
- **正常范围**：< 60%
- **告警阈值**：> 80%
- **查询**：`/actuator/metrics/process.cpu.usage`
- **处理建议**：定位高 CPU 线程

#### system.cpu.count
- **含义**：CPU 核数
- **正常范围**：固定值
- **查询**：`/actuator/metrics/system.cpu.count`
- **用途**：和负载对比，判断负载是否合理

#### system.load.average.1m
- **含义**：1 分钟平均负载
- **正常范围**：< CPU 核数
- **告警阈值**：> CPU 核数 × 2
- **查询**：`/actuator/metrics/system.load.average.1m`
- **处理建议**：负载高说明任务积压

---

### 2.2 磁盘指标

#### disk.free
- **含义**：磁盘剩余空间（字节）
- **标签**：`path`
- **正常范围**：> 20% 总空间
- **告警阈值**：< 10%
- **查询**：`/actuator/metrics/disk.free`
- **处理建议**：清理日志、临时文件

#### disk.total
- **含义**：磁盘总空间（字节）
- **查询**：`/actuator/metrics/disk.total`
- **用途**：和 disk.free 对比算使用率

---

### 2.3 网络指标

#### 无内置指标
Spring Boot Actuator 默认不暴露网络指标。如需监控，可通过：
- Linux：`/proc/net/dev`
- 第三方：Micrometer + Prometheus Node Exporter

**关注点**：
- 网络接收/发送字节数
- TCP 连接数
- 丢包率

## 三、HTTP / Web 指标

### 3.1 请求指标

#### http.server.requests
- **含义**：HTTP 请求统计
- **标签**：
  - `uri`：请求路径
  - `method`：HTTP 方法
  - `status`：响应状态码
  - `outcome`：SUCCESS / CLIENT_ERROR / SERVER_ERROR
- **关注字段**：
  - `count`：请求总数
  - `totalTime`：总耗时
  - `max`：最大耗时
- **正常范围**：
  - 平均耗时 < 200ms
  - 错误率 < 1%
- **告警阈值**：
  - 平均耗时 > 1s
  - 错误率 > 5%
- **查询**：
  - 全部：`/actuator/metrics/http.server.requests`
  - 按 URI：`/actuator/metrics/http.server.requests?tag=uri:/orders`
  - 按状态：`/actuator/metrics/http.server.requests?tag=status:500`
- **处理建议**：
  - 耗时高 → 查慢查询、下游依赖
  - 错误率高 → 查日志

---

## 九、指标与故障的对应关系

| 故障现象       | 优先查询的指标                                               |
| -------------- | ------------------------------------------------------------ |
| 服务响应慢     | `http.server.requests`、`system.cpu.usage`、`jvm.memory.used` |
| 服务不可用     | `/actuator/health`、`process.uptime`                         |
| CPU 高         | `system.cpu.usage`、`process.cpu.usage`、`jvm.threads.live`  |
| 内存泄漏       | `jvm.memory.used`、`jvm.gc.live.data.size`、`jvm.memory.usage.after.gc` |
| GC 频繁        | `jvm.gc.pause`、`jvm.gc.memory.promoted`                     |
| 线程池满       | `tomcat.threads.busy`、`jvm.threads.states`                  |
| 连接池耗尽     | `hikaricp.connections.active`、`hikaricp.connections.pending` |
| 慢查询         | `hikaricp.connections.usage`、`http.server.requests`         |
| 缓存问题       | `cache.gets`、`cache.evictions`、`redis.commands.latency`    |
| 磁盘满         | `disk.free`                                                  |
| 文件描述符耗尽 | `process.files.open`                                         |
| 启动慢         | `application.ready.time`                                     |
| 频繁重启       | `process.uptime`                                             |
| 错误率上升     | `http.server.requests`、`logback.events`                     |
| 请求量突增     | `http.server.requests`                                       |
| 业务异常       | `orders.failed.count`、`users.login.failed`                  |

## 十一、指标查询示例

### 查询 CPU 使用率
```
GET /actuator/metrics/system.cpu.usage
```

返回：
```json
{
  "name": "system.cpu.usage",
  "measurements": [
    { "statistic": "VALUE", "value": 0.92 }
  ]
}
```

### 查询 HTTP 请求数
```
GET /actuator/metrics/http.server.requests
```

返回：
```json
{
  "name": "http.server.requests",
  "measurements": [
    { "statistic": "COUNT", "value": 1250 },
    { "statistic": "TOTAL_TIME", "value": 125.5 },
    { "statistic": "MAX", "value": 2.3 }
  ]
}
```

### 查询指定 URI 的请求
```
GET /actuator/metrics/http.server.requests?tag=uri:/orders
```

### 查询指定状态的请求
```
GET /actuator/metrics/http.server.requests?tag=status:500
```

## 十二、使用建议

### 对智能体的意义

1. **RAG 检索**：用户问"CPU 高怎么办"，手册会召回"CPU 指标"+"故障处理手册 4.2 节"
2. **工具调用**：用户问"订单服务现在 CPU 多少"，工具调用 `/actuator/metrics/system.cpu.usage`
3. **阈值判断**：智能体根据阈值判断"当前 92%，属于严重级别"

### 阈值可调

上表阈值为通用推荐值，实际项目应根据：
- 服务的重要程度
- 业务特点（峰值、抖动）
- 历史基线

进行调整。

### 指标分层

- **一级指标**（必看）：CPU、内存、HTTP 耗时、错误率、健康状态
- **二级指标**（排查用）：GC、线程、连接池、磁盘
- **三级指标**（专项）：缓存、业务指标、文件描述符

智能体在处理问题时，应**从一级指标开始，逐层深入**。
