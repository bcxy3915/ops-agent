# 应急预案

## 1. 故障等级定义

| 等级 | 定义                         | 响应时间 | 通知范围    |
| ---- | ---------------------------- | -------- | ----------- |
| P0   | 核心服务不可用，影响全部用户 | 5 分钟   | 全员 + 领导 |
| P1   | 核心服务降级，影响部分用户   | 15 分钟  | 运维 + 开发 |
| P2   | 非核心服务异常               | 1 小时   | 运维        |
| P3   | 轻微问题，不影响业务         | 1 天     | 记录        |

## 2. P0 故障处理流程

1. **发现**：监控告警或用户反馈
2. **确认**：值班人员 5 分钟内确认
3. **通知**：立即通知技术负责人和领导
4. **止损**：优先恢复服务（重启、回滚、切流量）
5. **定位**：服务恢复后分析根因
6. **复盘**：24 小时内输出故障报告

## 3. P1 故障处理流程

1. 值班人员 15 分钟内响应
2. 通知相关开发
3. 按手册排查
4. 2 小时内输出处理记录

## 4. 常见应急操作

### 4.1 服务重启

- 适用：内存泄漏、CPU 高、死锁
- 风险：短暂服务不可用（约 30 秒）

### 4.2 服务回滚

- 适用：新版本引入故障
- 风险：回滚期间功能异常

### 4.3 流量切换

- 适用：单机房故障
- 操作：切换 DNS 或负载均衡

### 4.4 限流降级

- 适用：流量突增
- 操作：在网关开启限流规则
