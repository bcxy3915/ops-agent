# LangChain4j 核心链路查漏补缺

日期：2026-11-08。

本次检查覆盖模型工具调用、PG 向量读写与权限隔离、页面 SSE 契约、重启后记忆回填和告警诊断。检查方式为实现审计、生产组件装配、Mock 回归和本地 HTTP 协议夹具；没有访问真实模型、PostgreSQL 或浏览器页面，没有发送邮件、执行数据库脚本、重建索引或重启服务。

## 1. 已发现并修复

| 范围 | 问题 | 修复及行为 |
| --- | --- | --- |
| 同步聊天 | 只调用 Agent，没有保存会话和本轮消息 | 同步、流式共用准备逻辑：校验会话归属 → 预加载历史 → 保存当前问题；同步成功后保存助手答案 |
| 会话归属 | 既有会话未检查所属用户名；流式准备异常被吞掉 | 拒绝向其他用户会话提问；准备或用户消息落库失败即终止，不继续检索或调用模型 |
| 数据库租户隔离 | 表已有 tenant_id，但聊天实体、查询与写入未使用 | 补充实体映射；会话和消息查询限定当前可信租户，插入显式写入租户；无租户拒绝访问。最新消息批量查询所用 ID 取自已限定租户的聚合查询 |
| 内存租户隔离 | 记忆键只有用户名与 sessionId，跨租户同名会话可碰撞 | 记忆键加入租户；读写和清理缓存均检查标识租户与执行上下文一致 |
| 历史展示 | 页面历史按 createdAt 排序，与异步保存和冷启动排序不一致 | 页面历史与回填统一按自增 ID 排序 |
| BM25 审核过滤 | PUBLIC 和旧内置来源分支忽略明确的未审核状态 | 明确 DRAFT、PENDING、REJECTED 状态不可检索；保留缺少审核字段的旧向量兼容规则 |
| BM25 召回 | 先取固定倍数候选再过滤权限，其他租户高分结果可能挤掉可见文档 | 可见性过滤移至排序、topK 截断之前，增加大量不可见候选的回归场景 |
| 结构化网关 | JSON null 或首个 JSON 后追加其他内容未严格拒绝 | 拒绝空结果和尾随 JSON，解析错误继续向诊断失败路径传播 |
| 告警诊断 | 空对象、缺少证据/建议或越界置信度可能保存为 SUCCESS | 保存前校验根因、非空证据和建议、0–100 置信度；无效结果记 FAILED。空白追问答案也记 FAILED |
| 页面 SSE | 未收到 DONE 的 EOF 仍调用成功回调 | 前端改为错误回调，保留已收到的部分答案；补充分片、多行、引用、正常结束和提前断流测试 |

前端改动位于同级独立仓库 `ops-agent-frontend`，需要与本后端修改分别提交。两个仓库均未自动提交。

## 2. 已检查的现有机制

### 模型与工具

生产同步和流式 Agent 均由 LangChain4jConfig 组装，使用四个只读工具门面和原领域服务权限检查。生产配置限制最多八轮工具调用；参数及工具执行错误按调用失败处理。ContextAwareStreamingChatModel 在回调中恢复请求权限上下文，执行后恢复线程原上下文。

本地协议夹具覆盖健康查询后继续指标查询、工具结果回传下一轮模型以及中文流式响应。本次将流式工具链测试改为直接调用生产配置工厂，组合真实的 ConversationChatMemoryStore 和 LangChain4jKnowledgeContentRetriever，验证异步工具轮次与租户记忆校验可以协同运行。工具服务和检索底层仍是 Mock，不代表真实模型会正确选择工具。

### 向量存储

LangChain4jPgVectorStore 在 SQL 内限定 APPROVED 和可见范围，再执行距离筛选、排序及 LIMIT；租户、部门和用户名使用绑定参数。空部门集合不会变为同租户全部部门，个人知识同时限定租户与作者。

写入按十条分批，通过 Spring 事务代理覆盖整个 write 调用。新增回归让第二批数据库操作失败，验证整次调用进入 rollback 而非 commit。该测试使用模拟事务管理器和 JDBC，只证明事务装配及失败传播，真实 PG 回滚、表维度和实际数据隔离仍待验收。

### 记忆与告警

新仓库实例从持久化服务恢复用户与助手消息，证明恢复不依赖旧仓库缓存；同时验证跨租户同名会话隔离、历史预加载先于当前问题保存。真正的进程重启与数据库持久性仍需实际环境确认。

诊断保留事件、规则、快照、租户及部门关联；模型失败记录 FAILED。原告警编排已覆盖快照失败跳过诊断、诊断失败仍发送基础通知，未改变告警评估和通知状态机。

## 4. 实际环境验收步骤

按以下顺序执行，避免把 Mock 通过当作线上链路通过。

1. **工具调用**：登录后询问已注册服务是否健康；再要求仅在异常时查询 CPU 或线程指标。核对业务服务实际数据、工具调用结果和最终回答；无权限服务应拒绝，不得返回其他部门数据。
2. **向量与审核**：在专用测试租户上传含唯一检索词的文档，发布并等待索引完成；检索该词，核对 chunk、向量和引用。草稿及驳回文档不得命中；模型失败时索引任务应报告失败并可重试。
3. **数据隔离**：准备两个租户、同名用户和同一 sessionId，分别聊天并查看历史；切换用户及租户后不应看到另一方历史。分别验证 PUBLIC、TENANT、部门子树、PERSONAL 文档；无部门普通用户不能看到部门知识。
4. **SSE**：页面发送长中文问题，核对答案增量、引用和正常完成；主动停止应保留部分答案。断网或模型中途失败应提示失败并解除输入禁用，不能误报成功。
5. **重启回填**：分别通过同步和流式入口写入带唯一事实的问答，等待助手消息落库后重启后端；用原会话追问该事实，确认按 ID 顺序恢复且当前问题不重复。
6. **告警诊断**：对测试服务注入可恢复故障，核对事件 → 快照 → 诊断 → 通知关联；追加追问应新增记录。模拟超时、非法 JSON、空诊断对象时，诊断应 FAILED，基础告警通知仍可继续。
7. **真实事务**：仅在专用测试库中制造第二批向量写入失败，核对第一批也未提交；本轮没有自动执行此步骤。

## 5. 验收前注意事项与后续优化

- 需要重启后端以加载修复；前端开发服务通常支持热更新，部署环境需更新构建产物。
- 本次复用已有 tenant_id 列，没有新增 DDL。旧代码若曾将其他租户的聊天默认写入 t-default，修复后这些历史不会自动归入正确租户；需要根据可信归属核查后再单独修复，不能仅凭用户名批量迁移。
- 旧进程内记忆键格式发生变化，但未持久化到数据库；重启后会从 ops_message 重新恢复。
- Agent RAG 与展示引用仍各检索一次；诊断上下文和引用也分别检索，不能保证每次引用集合完全等同于模型输入。这是后续统一检索快照的优化项。
- 流式首片段前仍无法保证立刻取消底层 HTTP，已有取消保护阻止后续工具开始执行。
- 未在本轮引入自动部署、回滚、MCP、多 Agent 或复杂工作流。
