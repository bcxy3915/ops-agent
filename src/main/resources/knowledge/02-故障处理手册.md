# 故障处理手册

本文档覆盖运维中常见的故障类型。每个故障按"现象 → 常见原因 → 排查步骤 → 处理方案 → 预防措施"结构说明。

---

## 一、应用层故障

### 1.1 服务响应慢

**现象**
- 接口平均响应时间超过 1 秒
- 用户反馈"页面卡"、"请求超时"
- 监控显示 P99 耗时飙升

**常见原因**
- CPU 使用率过高（> 80%）
- JVM 内存不足，频繁 GC
- 数据库慢查询
- 下游服务超时
- 线程池耗尽
- 锁竞争激烈
- 网络延迟

**排查步骤**
1. 查询服务健康状态：`/actuator/health`
2. 查询 CPU：`/actuator/metrics/system.cpu.usage`
3. 查询 JVM 内存：`/actuator/metrics/jvm.memory.used`
4. 查询 GC：`/actuator/metrics/jvm.gc.pause`
5. 查询 HTTP 耗时：`/actuator/metrics/http.server.requests`
6. 查询线程池：`/actuator/metrics/executor.active`
7. 检查数据库慢查询日志
8. 检查下游服务状态

**处理方案**
- CPU 高 → 检查死循环，考虑扩容
- 内存不足 → 调整 JVM 堆参数或重启
- 慢查询 → 优化 SQL、加索引
- 下游超时 → 联系下游或加熔断
- 线程池满 → 调整线程池大小

**预防措施**
- 配置接口耗时告警（P99 > 1s）
- 定期做压测
- 加缓存减少数据库压力
- 下游调用加超时和熔断

---

### 1.2 服务不可用（502/503）

**现象**
- 网关返回 502 Bad Gateway 或 503 Service Unavailable
- 健康检查失败
- 用户完全无法访问

**常见原因**
- 服务进程崩溃
- 端口被占用
- 健康检查失败被摘除
- 依赖的数据库不可用
- 容器 OOM 被杀
- 部署中断

**排查步骤**
1. 查询服务健康状态
2. 检查进程是否存活：`ps -ef | grep java`
3. 检查端口占用：`netstat -ano | findstr 8081`
4. 检查数据库连接
5. 查看服务日志：`tail -f /var/log/order-service/app.log`
6. 检查容器状态：`docker ps -a`

**处理方案**
- 进程崩溃 → 查看日志定位，重启服务
- 端口占用 → 杀掉占用进程
- 数据库不可用 → 联系 DBA
- 容器 OOM → 调整容器内存限制

**预防措施**
- 配置进程存活监控
- 配置健康检查自动重启
- 加内存限制和 OOM 告警

---

### 1.3 接口超时

**现象**
- 接口返回 timeout 错误
- 调用方收到 SocketTimeoutException
- 特定接口偶发超时

**常见原因**
- 接口逻辑复杂，处理时间长
- 数据库慢查询
- 下游服务响应慢
- 网络抖动
- 线程池排队

**排查步骤**
1. 查询接口耗时分布：`/actuator/metrics/http.server.requests?tag=uri:/orders`
2. 检查该接口的数据库查询
3. 检查下游调用耗时
4. 检查网络：`ping` 和 `traceroute`
5. 检查线程池排队数

**处理方案**
- 接口逻辑慢 → 异步化、拆分
- 慢查询 → 优化 SQL
- 下游慢 → 加超时 + 降级
- 网络抖动 → 加重试

**预防措施**
- 所有下游调用设置合理超时
- 接口设置 SLA，超过阈值告警

---

### 1.4 接口报错（4xx/5xx）

**现象**
- 接口返回 400/401/403/404/500 等错误
- 错误率突增

**常见原因**
- 400：参数校验失败
- 401：未认证
- 403：无权限
- 404：路径错误
- 500：服务端异常
- 502/503/504：网关或上游问题

**排查步骤**
1. 查询错误率：`/actuator/metrics/http.server.requests?tag=status:500`
2. 查看错误日志
3. 检查最近的变更
4. 检查请求参数
5. 检查认证和权限配置

**处理方案**
- 400 → 检查参数格式
- 401 → 检查 Token 是否过期
- 403 → 检查权限配置
- 404 → 检查路由配置
- 500 → 查看堆栈定位代码

**预防措施**
- 参数校验前置
- 统一异常处理
- 错误率告警

---

### 1.5 线程池耗尽

**现象**
- 接口大量超时
- 日志显示 "RejectedExecutionException"
- 线程池活跃数达到上限

**常见原因**
- 任务提交速度 > 处理速度
- 任务阻塞（等待下游、等待锁）
- 线程池配置过小
- 任务泄漏（未释放）

**排查步骤**
1. 查询线程池指标：`/actuator/metrics/executor.active`
2. 查询排队数：`/actuator/metrics/executor.queued`
3. jstack 导出线程栈，看线程状态
4. 检查任务是否有阻塞

**处理方案**
- 临时：调大线程池
- 长期：优化任务处理逻辑，异步化

**预防措施**
- 线程池隔离（不同业务用不同池）
- 配置拒绝策略
- 监控活跃数和排队数

---

### 1.6 死锁

**现象**
- 接口卡住不返回
- CPU 使用率不高
- jstack 显示 "Found one Java-level deadlock"

**常见原因**
- 多线程竞争多个锁，加锁顺序不一致
- 数据库死锁
- 嵌套锁

**排查步骤**
1. jstack 导出线程栈
2. 查找 "deadlock" 关键字
3. 分析锁的持有和等待关系
4. 检查数据库死锁日志

**处理方案**
- 临时：重启服务
- 长期：统一加锁顺序，减少锁粒度

**预防措施**
- 避免嵌套锁
- 使用 tryLock 带超时
- 定期做线程栈分析

---

### 1.7 死循环

**现象**
- CPU 使用率 100%
- 接口无响应
- 日志停止输出

**常见原因**
- 循环条件写错
- 递归无终止条件
- 哈希冲突导致链表成环

**排查步骤**
1. 查询 CPU 使用率
2. `top -H -p <pid>` 找到高 CPU 线程
3. jstack 导出线程栈，看线程在做什么
4. 定位问题代码

**处理方案**
- 临时：重启服务
- 长期：修复代码

**预防措施**
- 代码审查
- 单元测试覆盖边界条件

---

## 二、JVM 层故障

### 2.1 内存泄漏

**现象**
- 内存使用持续增长，不释放
- Full GC 后内存仍不下降
- 最终触发 OOM

**常见原因**
- 静态集合持续添加元素
- 缓存未设置过期
- 监听器未注销
- 线程池未关闭
- ThreadLocal 未清理
- 大对象未释放

**排查步骤**
1. 查询内存趋势：`/actuator/metrics/jvm.memory.used`
2. 查询 GC 频率：`/actuator/metrics/jvm.gc.pause`
3. `jmap -dump:format=b,file=heap.hprof <pid>` 导出堆快照
4. 用 MAT 或 VisualVM 分析对象占用
5. 对比两次快照，找出持续增长的对象

**处理方案**
- 临时：重启服务
- 长期：定位泄漏点，修复代码

**预防措施**
- 缓存设置过期时间
- ThreadLocal 用后 remove
- 定期做内存分析

---

### 2.2 OOM（堆内存溢出）

**现象**
- 日志出现 "java.lang.OutOfMemoryError: Java heap space"
- 服务崩溃或不可用

**常见原因**
- 堆内存配置过小
- 内存泄漏导致
- 大对象一次性加载
- 批量查询数据量过大

**排查步骤**
1. 查看 OOM 日志
2. 检查 JVM 堆参数：`jinfo -flags <pid>`
3. 分析堆快照
4. 检查是否有大批量操作

**处理方案**
- 临时：调大堆内存 `-Xmx`
- 长期：修复泄漏，优化批量操作

**预防措施**
- 合理设置堆大小
- 分页查询避免大结果集
- 内存告警

---

### 2.3 元空间溢出

**现象**
- 日志出现 "java.lang.OutOfMemoryError: Metaspace"

**常见原因**
- 动态生成类过多（反射、CGLIB 代理）
- 类加载器泄漏
- Metaspace 配置过小

**排查步骤**
1. 查看 Metaspace 使用：`/actuator/metrics/jvm.memory.used?tag=area:nonheap`
2. 检查动态代理使用情况
3. 检查类加载器数量

**处理方案**
- 临时：调大 `-XX:MaxMetaspaceSize`
- 长期：减少动态类生成

**预防措施**
- 合理配置 Metaspace
- 避免频繁创建类加载器

---

### 2.4 GC 频繁

**现象**
- GC 次数突增
- STW 停顿明显
- 接口响应抖动

**常见原因**
- 堆内存不足
- 对象创建速率高
- 大对象频繁创建
- GC 参数不合理

**排查步骤**
1. 查询 GC 指标：`/actuator/metrics/jvm.gc.pause`
2. 检查 GC 日志
3. 分析对象创建速率
4. 检查堆内存使用

**处理方案**
- 调大堆内存
- 优化 GC 参数（G1、ZGC）
- 减少临时对象创建

**预防措施**
- 配置 GC 日志
- 监控 GC 频率和停顿

---

### 2.5 CPU 使用率过高

**现象**
- CPU 持续 > 80%
- 系统负载高
- 接口响应慢

**常见原因**
- 死循环
- 频繁 GC
- 大量计算任务
- 线程数过多
- 正则回溯

**排查步骤**
1. 查询 CPU：`/actuator/metrics/system.cpu.usage`
2. `top -H -p <pid>` 找高 CPU 线程
3. 线程 ID 转 16 进制
4. jstack 查找对应线程栈
5. 定位问题代码

**处理方案**
- 临时：重启服务
- 长期：优化代码或扩容

**预防措施**
- 代码审查
- CPU 告警

---

### 2.6 线程数过多

**现象**
- 线程数持续增长
- 内存占用高
- 上下文切换频繁

**常见原因**
- 线程池配置过大
- 线程泄漏（未关闭）
- 每次请求创建新线程

**排查步骤**
1. 查询线程数：`/actuator/metrics/jvm.threads.live`
2. jstack 查看线程列表
3. 检查线程池配置

**处理方案**
- 复用线程池
- 关闭未使用的线程
- 调整线程池大小

**预防措施**
- 统一线程池管理
- 线程数告警

---

## 三、数据库层故障

### 3.1 连接池耗尽

**现象**
- 日志出现 "Connection is not available"
- 接口大量超时
- 等待连接的请求堆积

**常见原因**
- 连接未归还（忘记 close）
- 慢查询长时间占用连接
- 连接池配置过小
- 数据库连接数上限

**排查步骤**
1. 查询活跃连接：`/actuator/metrics/hikaricp.connections.active`
2. 查询等待连接：`/actuator/metrics/hikaricp.connections.pending`
3. 检查是否有慢查询
4. 检查代码是否正确关闭连接

**处理方案**
- 临时：调大连接池
- 长期：修复连接泄漏，优化慢查询

**预防措施**
- 使用 try-with-resources
- 连接池监控告警
- SQL 超时设置

---

### 3.2 慢查询

**现象**
- SQL 执行时间长
- 数据库 CPU 高
- 接口响应慢

**常见原因**
- 缺少索引
- 索引失效
- 全表扫描
- 大表 JOIN
- 数据量过大

**排查步骤**
1. 开启慢查询日志
2. 分析慢 SQL
3. 用 EXPLAIN 分析执行计划
4. 检查索引使用情况

**处理方案**
- 加索引
- 优化 SQL
- 分库分表

**预防措施**
- SQL 审查
- 慢查询告警
- 定期分析执行计划

---

### 3.3 数据库死锁

**现象**
- 日志出现 "Deadlock found"
- 事务回滚

**常见原因**
- 多事务竞争资源，加锁顺序不一致
- 长事务
- 间隙锁

**排查步骤**
1. 查看数据库死锁日志
2. 分析涉及的事务和 SQL
3. 检查加锁顺序

**处理方案**
- 统一加锁顺序
- 缩短事务时间
- 降低隔离级别（谨慎）

**预防措施**
- 事务尽量短
- 批量操作排序

---

### 3.4 主从延迟

**现象**
- 从库数据落后主库
- 读从库数据不一致

**常见原因**
- 主库写入量大
- 从库性能差
- 大事务
- 网络延迟

**排查步骤**
1. 查询 `SHOW SLAVE STATUS` 的 `Seconds_Behind_Master`
2. 检查主库写入量
3. 检查从库性能

**处理方案**
- 优化大事务
- 提升从库性能
- 关键读走主库

**预防措施**
- 监控主从延迟
- 大事务拆分

---

### 3.5 数据库不可用

**现象**
- 连接被拒绝
- 所有接口报数据库错误

**常见原因**
- 数据库宕机
- 连接数达到上限
- 网络不通
- 磁盘满

**排查步骤**
1. 尝试连接数据库
2. 检查数据库进程
3. 检查磁盘空间
4. 检查连接数

**处理方案**
- 重启数据库
- 清理磁盘
- 联系 DBA

**预防措施**
- 数据库高可用
- 磁盘监控

---

### 3.6 连接泄漏

**现象**
- 活跃连接数持续增长
- 最终连接池耗尽

**常见原因**
- 代码未正确关闭连接
- 异常路径未释放
- 连接池配置问题

**排查步骤**
1. 监控连接数趋势
2. 检查代码中的连接使用
3. 用连接池的泄漏检测功能

**处理方案**
- 修复代码
- 开启泄漏检测

**预防措施**
- try-with-resources
- 代码审查

---

## 四、中间件层故障

### 4.1 Redis 不可用

**现象**
- 缓存读写失败
- 接口报 Redis 连接错误

**常见原因**
- Redis 宕机
- 连接数满
- 内存满
- 网络不通

**排查步骤**
1. 尝试连接 Redis：`redis-cli ping`
2. 检查 Redis 进程
3. 检查内存使用：`redis-cli info memory`
4. 检查连接数

**处理方案**
- 重启 Redis
- 清理过期 key
- 扩容

**预防措施**
- Redis 高可用
- 内存告警
- 降级方案

---

### 4.2 缓存击穿

**现象**
- 某个热点 key 过期瞬间，大量请求打到数据库
- 数据库压力骤增

**常见原因**
- 热点 key 过期
- 高并发访问

**处理方案**
- 互斥锁重建缓存
- 热点 key 永不过期
- 提前预热

**预防措施**
- 热点 key 识别
- 缓存预热

---

### 4.3 缓存穿透

**现象**
- 大量请求查询不存在的 key
- 请求全部打到数据库

**常见原因**
- 恶意攻击
- 查询不存在的 ID

**处理方案**
- 布隆过滤器
- 空值缓存

**预防措施**
- 参数校验
- 限流

---

### 4.4 缓存雪崩

**现象**
- 大量 key 同时过期
- 数据库瞬间压力暴增

**常见原因**
- 缓存集中过期
- Redis 宕机

**处理方案**
- 过期时间加随机值
- 多级缓存
- Redis 高可用

**预防措施**
- 过期时间分散
- 缓存预热

---

### 4.5 MQ 消息堆积

**现象**
- 队列消息数持续增长
- 消费延迟

**常见原因**
- 消费速度 < 生产速度
- 消费者宕机
- 消费逻辑慢

**排查步骤**
1. 查询队列深度
2. 检查消费者状态
3. 检查消费逻辑耗时

**处理方案**
- 增加消费者
- 优化消费逻辑
- 临时丢弃非关键消息

**预防措施**
- 队列深度告警
- 消费者扩容

---

### 4.6 MQ 消息丢失

**现象**
- 消息发送成功但未消费
- 数据不一致

**常见原因**
- 生产者发送失败未重试
- Broker 宕机丢失消息
- 消费者处理失败未 ack

**处理方案**
- 生产者确认机制
- Broker 持久化
- 消费者手动 ack + 重试

**预防措施**
- 消息持久化
- 死信队列
- 消息补偿

---

## 五、网络层故障

### 5.1 网络超时

**现象**
- 调用外部服务超时
- SocketTimeoutException

**常见原因**
- 网络抖动
- 对端处理慢
- 带宽不足
- 防火墙

**排查步骤**
1. `ping` 检查连通性
2. `traceroute` 检查路由
3. 检查带宽使用
4. 检查防火墙规则

**处理方案**
- 加重试
- 加超时
- 联系网络团队

**预防措施**
- 超时配置
- 熔断降级

---

### 5.2 DNS 解析失败

**现象**
- UnknownHostException
- 域名无法解析

**常见原因**
- DNS 服务器故障
- 域名配置错误
- 本地 hosts 配置问题

**排查步骤**
1. `nslookup` 检查解析
2. 检查 DNS 配置
3. 检查 hosts 文件

**处理方案**
- 切换 DNS
- 修复域名配置

**预防措施**
- 多 DNS 服务器
- 本地缓存
