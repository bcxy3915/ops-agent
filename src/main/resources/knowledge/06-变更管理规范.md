# 变更管理规范（Change Management）

> 文档元数据
> - 版本：v1.0
> - 适用范围：ops-agent 系统及被监控服务的代码、配置、数据库、依赖变更
> - 目标：变更可审计、可回滚、可追溯（审计日志表 ops_audit_log 支持）

## 1. 变更分级

| 级别 | 定义 | 典型变更 | 审批要求 | 变更窗口 |
| --- | --- | --- | --- | --- |
| 低风险（L1） | 不影响核心功能、可随时回滚 | 文档更新、注释修改、非关键配置调整 | 无需审批，记录即可 | 任意时间 |
| 中风险（L2） | 影响部分功能、回滚较容易 | 新增接口、告警规则调整、依赖小版本升级 | 负责人审批 | 非高峰时段 |
| 高风险（L3） | 影响核心服务、回滚复杂 | 数据库表结构变更、核心服务重构、框架升级、端口/网络变更 | 项目负责人审批 + 演练 | 计划变更窗口（如周末/夜间） |

## 2. 变更流程（RFC，参考 ITIL）

```
1. 提交变更申请（RFC：变更内容、原因、影响范围、风险评估、回滚方案、测试结果、时间窗口）
  │
  ▼
2. 评审审批（按风险分级：标准变更→预授权；常规变更→负责人审批；重大变更→CAB+项目负责人审批）
  │
  ▼
3. 实施（按变更方案执行，双人操作：一人执行一人复核，全程记录，参考《04-部署手册.md》）
  │
  ▼
4. 验证（功能验证 + 健康检查 + 告警观察；验证后观察期监控）
  │
  ▼
5. 回滚预案（失败时按预写回滚方案执行，变更关闭或回滚）
  │
  ▼
6. 记录（变更记录写入审计日志，必要时复盘）
```

### 2.1 评审组织
- **CAB（变更顾问委员会）**：由负责人、技术专家、相关服务 owner 组成；仅重大变更（L3）召开
- **标准变更**（L1）：走预授权，无需逐次审批，按目录执行
- **常规变更**（L2）：负责人审批
- **重大变更**（L3）：CAB 评审 + 项目负责人审批 + 演练

### 2.2 变更冻结期（Change Freeze）
- 节假日、大促、重要发布前冻结非紧急变更（如重大活动前 3 天 - 活动结束后 1 天）
- 冻结期内仅允许紧急修复（需负责人特批）

## 3. 变更实施规范

- **先在测试环境验证**：所有 L2/L3 变更先在 dev/test 环境验证通过后再上生产
- **灰度/分批**：L3 变更建议分批发布（如先 1 台验证再全量）
- **数据库变更**：表结构变更需备份；通过 `init-scripts` 或手动 SQL 执行，执行前确认影响
- **配置变更**：通过配置文件管理，变更后重启并验证；敏感配置（密码/Token）不入库、不入日志
- **知识库变更**：knowledge 目录文档变更后重启触发 DocumentLoader 增量加载，验证向量库更新

## 4. 回滚策略

| 变更类型 | 回滚方式 |
| --- | --- |
| 代码发布 | git 回滚到上一版本重新构建部署 |
| 数据库结构 | 使用变更前备份恢复；或执行逆向迁移脚本 |
| 配置变更 | 恢复上一版配置并重启 |
| 知识库文档 | 恢复上一版文档并重启 |

## 5. 变更审计

- 系统内置审计日志（`ops_audit_log` 表），记录关键操作（登录、服务注册、规则变更等）
- L2/L3 变更必须填写变更记录，便于复盘与追溯
- 变更记录建议包含：时间、操作人、变更内容、审批人、验证结果、回滚状态

## 6. 变更窗口建议

- L1：任意时间
- L2：工作日下午（避开高峰），如 14:00-18:00
- L3：计划窗口（周末/夜间），并提前通知相关方
