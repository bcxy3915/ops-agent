# 监控指标字典（Metric Dictionary）

> 文档元数据
> - 版本：v1.1
> - 原则：只收录当前系统（Spring Boot Actuator + PostgreSQL + Docker 环境）真实可采集的指标；阈值标注依据（行业标准默认值 + 可配置）；不收录虚构/推荐性指标
> - 指标来源：`/actuator/metrics` 端点（服务侧）+ 系统自定义采集（ops-agent 侧）
> - 阈值依据：awesome-prometheus-alerts 社区标准、Prometheus 官方告警最佳实践、阿里云 ARMS 默认阈值

## 1. 指标采集机制

- 服务通过 Spring Boot Actuator 暴露 `health, metrics, info` 端点
- 指标命名遵循 Actuator/Micrometer 标准命名（`jvm.*`、`system.*`、`http.*`、`hikaricp.*`、`disk.*` 等）
- 采样数据写入 `metric_sample` 表：`(service, metric, value, sampled_at)`，索引 `(service, metric, sampled_at)`
- 查询入口：`GET /api/metrics/history?service=&metric=`

## 3. 阈值配置说明

- 告警规则存储在 `alert_rule` 表：`(service, metric, operator, threshold, compare_mode, duration_seconds, silence_seconds, enabled)`
- **行业标准默认值**：上表 Warning/Critical 为开箱即用默认值，可在「告警规则」页面调整
- **告警分级原则**：Warning（警告，需关注）与 Critical（严重，需立即处理）两级，避免告警疲劳；每条告警必须可行动（actionable）
- **防抖动**：duration_seconds 默认 60（持续 N 秒才触发），用于过滤瞬时抖动
- **operator 支持**：`>` `>=` `<` `<=` `==` `!=`
- **compare_mode**：`THRESHOLD`（阈值比较）/ `RATE`（速率比较，如增长率）
- **silence_seconds**：触发后静默 N 秒，防止告警风暴

## 4. 不收录的指标（设计决策）

以下指标**不在**本字典中，避免虚构/误导：
- 业务自定义指标（如 `orders.created.count`、`todo.created.count` 等虚构业务计数）——除非业务服务真实暴露对应 Actuator 指标
- 未配置采集的中间件指标（如 redis.* / cache.*，当前系统未接入 Redis）——仅在有真实中间件接入后补充
- 无法从当前 Actuator 端点获取的指标——避免「看着有、采不到」

> 说明：新增真实指标时按上述规范补充，并更新「阈值依据」字段。

## 5. 指标查询方式

- **页面**：前端「指标监控」页（`/metrics`）
- **API**：`GET /api/metrics/history?service=todo-service&metric=system.cpu.usage&start=&end=`
- **聊天**：问运维智能体「查看 todo-service 的 CPU 使用率」
- **原始端点**：`GET http://localhost:8081/actuator/metrics/system.cpu.usage`（验证指标真实存在）
