# 值班与响应流程（On-Call & Response）

> 文档元数据
> - 版本：v1.0
> - 目标：告警有人响应、事件有人处理、交接无缝衔接
> - 联动：告警通知渠道、应急预案分级、升级路径

## 1. 值班安排

### 1.1 值班角色
| 角色 | 职责 | 人数 |
| --- | --- | --- |
| 主值班（Primary On-Call） | 第一时间响应告警、处置事件 | 1 人/班次 |
| 备值班（Secondary On-Call） | 主值班不可达/升级时介入 | 1 人/班次 |
| 服务负责人（Owner） | 对应服务故障升级目标（ops_service.owner） | 按服务 |
| 项目负责人 | SEV0/SEV1 升级终点、重大决策 | 1 人 |

### 1.2 值班周期
- 建议班次：每周轮换（周一 00:00 - 下周一 00:00），或按项目规模日班/夜班
- 排班表应提前发布，值班人员当日保持手机/即时通讯可达
- 备值班必须知晓当日主值班及升级路径

## 2. 告警响应规则

### 2.1 响应时限（与《05-应急预案.md》一致）
| 事件级别 | 首次响应 | 处置目标 |
| --- | --- | --- |
| SEV0 | ≤5 分钟 | 立即处理 |
| SEV1 | ≤15 分钟 | 15 分钟恢复或升级 |
| SEV2 | ≤30 分钟 | 30 分钟恢复或升级 |
| SEV3 | ≤4 小时 | 当日处理 |
| SEV4 | 记录 | 排期处理 |

### 2.2 告警处理步骤（值班人员）
```
1. 接收告警（通知渠道：邮件/IM/系统消息）
2. 登录系统 → 查看告警事件详情（alert_event）
3. 查看服务状态与指标（服务管理 / 指标监控）
4. 按《02-故障处理手册.md》对应场景处置
5. 处理完成后确认告警解除，记录处理过程
6. 无法解决 → 按升级路径上报（15 分钟/30 分钟时限）
```

## 3. 交接班规范

### 3.1 交接时机
- 班次结束前 15 分钟完成交接
- 事件处理中（未恢复）必须当面/电话交接，不能直接结束班次

### 3.2 交接清单（书面交接）
1. **进行中事件**：事件级别、影响、已做处置、待办、下一步
2. **未恢复告警**：规则名、服务、触发时间、当前状态
3. **近期变更**：L2/L3 变更、配置调整、知识库更新
4. **待办事项**：待优化点、待复盘事件
5. **值班注意**：已知问题、近期风险、联系信息（负责人/备值班）
6. **工具账号状态**：值班工具/系统账号是否可用、是否有异常（参考 On-Call 交接规范）

### 3.3 交接形式
- **书面交接文档 + 口头/会议交接**：先书面整理，再当面确认关键项
- **交接双方确认签字**：避免信息遗漏责任不清
- **固定交接时间**：如每天 10:00（或班次结束前 15 分钟）

### 3.4 值班轮换与保障
- 轮班制：日班/夜班/周末班，避免连续值班
- 值班补偿机制（如调休/补贴），保障响应质量

### 3.3 交接模板
```
交接日期：YYYY-MM-DD
交接人：___（主值班） → ___（接值班）

1. 进行中事件：
   - [事件ID/服务/级别/当前状态/下一步]
2. 未恢复告警：
   - [规则/服务/触发时间/处置中状态]
3. 近期变更：
   - [变更内容/时间/影响/是否已回滚]
4. 待办事项：
   - [事项/负责人/截止时间]
5. 值班注意：
   - [已知问题/风险/联系人]
```

## 4. 升级路径与沟通

- **升级规则**：响应超时 / 处置超时 / 事件升级 → 逐级上报
- **升级顺序**：主值班 → 备值班 → 服务负责人 → 项目负责人
- **升级方式**：即时通讯 + 电话（关键事件），项目群通报
- **值班不可达**：超过 5 分钟未响应告警 → 自动转备值班

## 5. 值班质量管理

- **告警有效性**：定期复盘告警准确率，误报过多需调规则（《03-指标字典.md》阈值）
- **响应记录**：每次响应与处置记录到事件/日志，供复盘
- **交接检查**：交接清单必须完整，避免信息丢失
- **培训**：新值班人员上岗前需熟悉《02-故障处理手册.md》《04-部署手册.md》《05-应急预案.md》

## 6. 常见值班 FAQ

- **收到告警但不知道哪个服务**：先看告警事件的服务字段，再到服务管理查状态
- **告警反复触发**：检查 duration_seconds / silence_seconds 配置，见《02-故障处理手册.md》第 6 节
- **通知没收到**：检查 notification_channel 配置与 notification_record 状态
- **值班期间要变更**：按《06-变更管理规范.md》分级，L2/L3 需审批，值班期间原则上只做止血类操作
