# 部署手册（Deployment Guide）

> 文档元数据
> - 版本：v1.0
> - 适用环境：Windows + Docker Desktop（PostgreSQL 容器化）+ 本地 Java 进程
> - 部署对象：ops-agent 后端、ops-agent-frontend 前端、todo-service 示例服务、ops-postgres 数据库

## 1. 架构总览

```
┌─ ops-agent-frontend (Vue3, dev:5173 / prod:dist) ─┐
│                                                     │
└────────────── HTTP ──▶ ops-agent (8080) ◀───────────┘
                              │
                              ├── JDBC ──▶ ops-postgres (5433, Docker pgvector:pg16)

                              └── HTTP ──▶ todo-service (8081, 被监控)
```

## 3. 数据库部署（PostgreSQL + pgvector）

项目根目录 `ops-ai-agent` 下的 `docker-compose.yml` 定义数据库：

```yaml
services:
  postgres:
    image: pgvector/pgvector:pg16
    container_name: ops-postgres
    ports:
      - "${DB_PORT:-5433}:5432"
    environment:
      POSTGRES_DB: opsdb
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-postgres}
    volumes:
      - ops_pgdata:/var/lib/postgresql/data
      - ./init-scripts:/docker-entrypoint-initdb.d
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d opsdb"]
      interval: 10s
      timeout: 5s
      retries: 5
volumes:
  ops_pgdata:
```

### 3.1 启动数据库
```powershell
cd "D:\my projects\java ai\ops-agent\ops-ai-agent"
docker compose up -d
```

### 3.2 验证数据库
```powershell
docker ps --filter "name=ops-postgres"
docker exec ops-postgres psql -U postgres -d opsdb -c "SELECT 1;"
docker exec ops-postgres psql -U postgres -d opsdb -c "\dt"   # 查看表
```

### 3.3 初始化脚本
`init-scripts/` 目录包含两份脚本（首次启动容器时按文件名顺序自动执行）：
- `schema.sql`：全量最终表结构（已合并历史 ALTER TABLE），含 pgvector 扩展、31 张表、索引、全部表和字段注释
- `seed.sql`：基础演示数据，含平台/企业租户、部门树、RBAC 角色与权限、不同角色的账号、示例服务

演示账号：
- 平台管理员：`admin / admin123`
- 企业管理员：`zhangwei@xinghai.com / ops123456`
- 部门管理员：`lina@xinghai.com / ops123456`
- 运维工程师：`wangqiang@xinghai.com / ops123456`
- 只读成员：`chenchen@xinghai.com / ops123456`

> 注意：init-scripts 仅在数据卷首次初始化时执行；重建表结构需手动执行 SQL。

### 3.4 数据持久化与备份
- 数据持久化在 Docker 命名卷 `ops_pgdata`
- 备份命令：
```powershell
docker exec ops-postgres pg_dump -U postgres -d opsdb -F c -f /tmp/opsdb.dump
docker cp ops-postgres:/tmp/opsdb.dump D:\backup\opsdb_$(Get-Date -Format yyyyMMdd).dump
```
- 恢复命令：
```powershell
docker cp D:\backup\opsdb_20261018.dump ops-postgres:/tmp/opsdb.dump
docker exec ops-postgres pg_restore -U postgres -d opsdb -c /tmp/opsdb.dump
```

## 4. ops-agent 后端部署

### 4.1 配置
- 主配置：`src/main/resources/application.yml`
- 本地覆盖：`src/main/resources/application-local.yml`（启用 `--spring.profiles.active=local`）
- 关键配置项：
  - 数据源：`jdbc:postgresql://localhost:5433/opsdb`
  - LLM：模型 API Key / 模型名（Spring AI）
  - 服务端口：`server.port=8080`

### 4.2 构建
```powershell
cd "D:\my projects\java ai\ops-agent\ops-ai-agent"
.\mvnw clean package -DskipTests=false    # 生产构建（含 494 个测试）
```

### 4.3 启动（开发）
```powershell

```

### 4.4 启动（生产 jar）
```powershell
java -jar target/ops-agent-core-*.jar --spring.profiles.active=prod
```

### 4.5 验证
```powershell
Invoke-WebRequest http://localhost:8080/actuator/health -UseBasicParsing | Select-Object StatusCode
```

## 7. 服务注册与启用监控

1. 启动 todo-service（8081）
2. 通过前端「服务管理」或 API `POST /api/services` 注册：
   ```json
   {
     "name": "todo-service",
     "baseUrl": "http://localhost:8081",
     "healthPath": "/actuator/health",
     "metricsPath": "/actuator/metrics",
     "owner": "项目组",
     "env": "dev"
   }
   ```
3. 确认 `ops_service` 表出现记录，状态经健康检查后为 UP
4. 配置告警规则（`alert_rule`）并启用

## 8. Docker Compose 生产部署最佳实践（参考）

> 参考来源：[Docker 官方生产环境最佳实践](https://docs.docker.com/compose/production/)、[Docker Compose 生产环境部署指南](https://shallowhave.github.io/2025/08/06/Docker-Compose-Production-Guide/)

### 8.1 镜像与构建
- 使用**固定版本 tag**（禁止 `latest`），确保可复现：`pgvector/pgvector:pg16`（当前即固定）
- 多阶段构建减小镜像体积；构建前扫描漏洞
- 生产使用私有镜像仓库，构建产物可追溯

### 8.2 健康检查（Healthcheck）
- 每个服务必须配置 healthcheck（HTTP/TCP/CMD），设置合理 `interval/timeout/retries/start_period`
- 依赖服务启动顺序：`depends_on` + `condition: service_healthy`（等数据库就绪再启动应用）
- 当前 postgres 已配置 healthcheck（`pg_isready`），建议应用服务也配置 `/actuator/health` 探测

### 8.3 资源限制与重启策略
- 每个服务设置 `cpus` / `mem_limit` / `reservations`，防止单容器耗尽宿主机资源
- 设置 `restart: unless-stopped`（或 `always`），崩溃自动拉起
- 生产关键服务建议宿主机级进程守护（如 Windows 服务、systemd）

### 8.4 日志管理
- 使用 `json-file` 或 `syslog` 驱动；配置 `max-size` / `max-file` 轮转，防止日志撑爆磁盘
- 日志输出到 stdout/stderr（不写容器内文件）；集中收集（ELK/Loki/云日志）
- 当前系统数据库日志量小，但**应用服务必须配置日志轮转**（logback `maxFileSize`/`maxHistory`）

### 8.5 数据持久化与安全
- 数据卷使用 **named volumes**（不用 bind mount），数据库卷定期备份
- 敏感配置（密码/Token）用 `.env` 或 secrets，**不写入 compose 文件明文**
- 只读文件系统 `read_only: true` + `tmpfs`（应用无写盘需求时）
- 自定义网络隔离；不暴露不必要端口；使用非 root 用户运行容器
- 生产大规模建议 Docker Swarm / K8s 编排替代单机 compose

### 8.6 部署流程建议
- compose 文件分 `base/override` 多环境（如 `docker-compose.yml` + `docker-compose.prod.yml`）
- 部署前先 `docker compose config` 验证配置合法性
- 上线前 pull + 检查依赖镜像；变更走《06-变更管理规范.md》

## 9. 部署检查清单

- [ ] JDK 21 可用（`java -version`）

## 10. 常见部署问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 端口被占用 8080/8081/5433 | 本地已有进程 | `netstat -ano \| findstr :8080` 定位后处理 |
| 数据库连接失败 | PostgreSQL 未启动 / 密码不符 | `docker compose up -d`，检查 `.env` |
| 知识库为空 | 文档未放对位置 / 未重启 | 确认 knowledge 目录有 md/pdf，重启应用 |
| LLM 调用失败 | API Key 缺失/额度 | 检查 application-local.yml 与模型配置 |
