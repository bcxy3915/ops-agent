# 部署手册（Deployment Guide）

> 文档元数据
> - 版本：v1.0
> - 适用环境：Windows + Docker Desktop（MySQL 容器化）+ 本地 Java 进程
> - 部署对象：ops-agent 后端、ops-agent-frontend 前端、todo-service 示例服务、ops-mysql 数据库

## 1. 架构总览

```
┌─ ops-agent-frontend (Vue3, dev:8888 / prod:dist) ─┐
│                                                     │
└────────────── HTTP ──▶ ops-agent (18080) ◀───────────┘
                              │
                              ├── JDBC ──▶ ops-mysql (23306) + Elasticsearch (9200)
                              │
                              └── HTTP ──▶ todo-service (8081, 被监控)
```

## 3. 数据库部署（MySQL + Elasticsearch）

在项目根目录配置 `.env` 的 DB_PASSWORD，保留原有本地模型与邮件密钥。

```powershell
docker compose up -d mysql elasticsearch
python scripts/initialize-elasticsearch.py
docker compose ps
```

MySQL 地址为 localhost:23306/opsdb，ES 为 http://localhost:9200。当前仅用于本机开发，ES 关闭认证并仅绑定回环地址。

### 3.1 初始化脚本

MySQL 空数据卷首次启动执行 `init-scripts/mysql/schema.sql` 与 `seed.sql`，共 33 张表。已有环境执行对应增量脚本，不能靠重启重跑初始化。
ES 使用 `init-scripts/elasticsearch/knowledge-index.http` 定义索引、模板和别名，独立于业务建表脚本。

### 3.2 旧数据迁移

使用 `scripts/migrate-local-postgres-to-mysql.py` 先预检，再按交付说明执行迁移。旧 PostgreSQL 仅保留用于迁移与核对，不再作为当前业务库。

### 3.3 检索发布

文档先保存 MySQL 原文、分块及投递记录，ES 同步确认后发布。BUILDING 期间检查分块任务与 knowledge_search_projection 的 pending/attempts/last_error。

### 3.4 数据持久化与备份

MySQL 与 ES 均使用独立 Docker 命名卷。MySQL 使用 mysqldump 备份，交互输入密码；ES 使用快照仓库备份。恢复前先备份当前数据并确认目标环境，不得直接覆盖运行中的业务库。

```powershell
docker exec -it ops-mysql mysqldump -u root -p --single-transaction --result-file=/tmp/opsdb.sql opsdb
docker cp ops-mysql:/tmp/opsdb.sql D:\backup\opsdb.sql
```

详细切换、恢复边界及验证步骤见 `docs/mysql-es-migration.md`。

## 4. ops-agent 后端部署

### 4.1 配置
- 主配置：`src/main/resources/application.yml`
- 本地覆盖：`src/main/resources/application-local.yml`（启用 `--spring.profiles.active=local`）
- 关键配置项：
  - 数据源：`jdbc:mysql://localhost:23306/opsdb`
  - LLM：模型 API Key / 模型名（LangChain4j，ops-agent.ai.*）
  - 服务端口：`server.port=18080`

### 4.2 构建
```powershell
cd "D:\my projects\java ai\ops-agent\ops-ai-agent"
.\mvnw clean package -DskipTests=false    # 生产构建（包含测试）
```

### 4.3 启动（开发）
```powershell
.\mvnw spring-boot:run -Dspring-boot.run.profiles=local
```
启动时 DocumentLoader 自动增量加载 `src/main/resources/knowledge/` 下的 md/pdf 文档到向量库（按 source 去重，缺失则重建索引）。

### 4.4 启动（生产 jar）
```powershell
java -jar target/ops-agent-core-*.jar --spring.profiles.active=prod
```

### 4.5 验证
```powershell
Invoke-WebRequest http://localhost:18080/actuator/health -UseBasicParsing | Select-Object StatusCode
```


### 6.3 验证
- 打开 `http://localhost:8888`（dev）或部署后的站点
- 默认首页为对话页（`/` 重定向 `/chat`），侧栏含服务管理/指标监控/审计日志/用户管理

## 7. 服务注册与启用监控

1. 启动 todo-service（8081）
2. 通过前端「服务管理」或 API `POST /api/services` 注册：
   ```json
   {
     "name": "todo-service",
     "baseUrl": "http://localhost:8081",
     "healthPath": "/actuator/health",
     "metricsPath": "/actuator/metrics",
     "owner": "项目组",
     "env": "dev"
   }
   ```
3. 确认 `ops_service` 表出现记录，状态经健康检查后为 UP
4. 配置告警规则（`alert_rule`）并启用

## 8. Docker Compose 生产部署最佳实践（参考）

> 参考来源：[Docker 官方生产环境最佳实践](https://docs.docker.com/compose/production/)、[Docker Compose 生产环境部署指南](https://shallowhave.github.io/2025/08/06/Docker-Compose-Production-Guide/)

### 8.1 镜像与构建
- 使用**固定版本 tag**（禁止 `latest`），确保可复现：`mysql:8.4 与 elasticsearch:8.19.6`（当前即固定）
- 多阶段构建减小镜像体积；构建前扫描漏洞
- 生产使用私有镜像仓库，构建产物可追溯

### 8.2 健康检查（Healthcheck）
- 每个服务必须配置 healthcheck（HTTP/TCP/CMD），设置合理 `interval/timeout/retries/start_period`
- 依赖服务启动顺序：`depends_on` + `condition: service_healthy`（等数据库就绪再启动应用）
- 当前 MySQL 与 ES 已配置 healthcheck（容器健康检查），建议应用服务也配置 `/actuator/health` 探测

### 8.3 资源限制与重启策略
- 每个服务设置 `cpus` / `mem_limit` / `reservations`，防止单容器耗尽宿主机资源
- 设置 `restart: unless-stopped`（或 `always`），崩溃自动拉起
- 生产关键服务建议宿主机级进程守护（如 Windows 服务、systemd）

### 8.4 日志管理
- 使用 `json-file` 或 `syslog` 驱动；配置 `max-size` / `max-file` 轮转，防止日志撑爆磁盘
- 日志输出到 stdout/stderr（不写容器内文件）；集中收集（ELK/Loki/云日志）
- 当前系统数据库日志量小，但**应用服务必须配置日志轮转**（logback `maxFileSize`/`maxHistory`）

### 8.5 数据持久化与安全
- 数据卷使用 **named volumes**（不用 bind mount），数据库卷定期备份
- 敏感配置（密码/Token）用 `.env` 或 secrets，**不写入 compose 文件明文**
- 只读文件系统 `read_only: true` + `tmpfs`（应用无写盘需求时）
- 自定义网络隔离；不暴露不必要端口；使用非 root 用户运行容器
- 生产大规模建议 Docker Swarm / K8s 编排替代单机 compose

### 8.6 部署流程建议
- compose 文件分 `base/override` 多环境（如 `docker-compose.yml` + `docker-compose.prod.yml`）
- 部署前先 `docker compose config` 验证配置合法性
- 上线前 pull + 检查依赖镜像；变更走《06-变更管理规范.md》

- [ ] JDK 21 可用（`java -version`）
- [ ] Docker Desktop 运行中（`docker ps`）

## 10. 常见部署问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 端口被占用 18080/8081/23306 | 本地已有进程 | `netstat -ano \| findstr :18080` 定位后处理 |
| 数据库连接失败 | MySQL 未启动 / 密码不符 | `docker compose up -d`，检查 `.env` |
| 知识库为空 | 文档未放对位置 / 未重启 | 确认 knowledge 目录有 md/pdf，重启应用 |
| LLM 调用失败 | API Key 缺失/额度 | 检查 application-local.yml 与模型配置 |
